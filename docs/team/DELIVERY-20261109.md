## What each request asked for, and what shipped

**Multilingual.** Tamil is the default and the native voice; English is complete; Hindi is
machine-drafted and every one of its 394 strings is flagged `reviewRequired` and listed
against its English source in `docs/i18n/HINDI-REVIEW.md` for a native reviewer. Locale and
display are separate concepts (`yazhi-locale` vs the TAM/ENG/BOTH preference). Tamil text is
handled at grapheme/akṣara level (`@yazhi/i18n/tamil`), never by code-unit slicing. Adding a
fourth language is four steps, documented in `packages/i18n/README.md`.

**API.** One typed kernel (`src/lib/api`) behind a documented v1 surface
([`docs/API.md`](../API.md), live at `/api/openapi.json`): bubble manifests v1, a registry
with publish/review/withdraw and fail-closed maintainer gating, HMAC signing that degrades to
a warning, agents listed without their system prompts, manifest validation, and translation.
The browser never holds a server secret; `ports.ts` / `ports-local.ts` / `error.ts` keep the
`server-only` Circle session out of the client graph.

**Bubble UI.** `/app` implements the end state the repo's own proposal describes: an app is a
set of bubbles in one host — tray, canvas, composer led by Mission Control — with deep links,
back/forward, a keyboard map, one screen-reader announcement per completed reply, and the
on-device runtime so it works offline.

## Follow-up, same day

**Bubble-UI library localisation is done** (`packages/bubble/src/locales/`, 188 keys ×
ta/en/hi) and gap 1 below is closed:

- `<BubbleLocaleScope>` is mounted once, in `<LangProvider>`, so `/app`, `/chat`, the
  workspaces and the design book all read the library copy in the active locale. Props stay
  overrides; standalone (tests, an embedding host) the library answers in Tamil with
  English fallback.
- The catalogue is now checked, not just typed. `npm run i18n:check` resolves every
  `t("…")` against its file's `useBubbleT` namespace — and **found three keys filed under
  the wrong namespace** (`bubble.workspace.approvedBy`/`approvedTitle`,
  `bubble.commerce.total`), each of which was rendering as a dotted key on screen. Fixed.
- `npm run test:bubble` (14 tests) covers catalogue invariants, the lookup seam, and a
  source scan for bare English JSX text/attributes.
- Every Hindi line in the library is `{ origin: "mt", reviewRequired: true }` and appears
  in `docs/i18n/HINDI-REVIEW.md` (regenerated: 204 site + 190 chrome + 188 bubble rows).

**A real defect fell out of the browser pass: hydration was mismatching on every
non-Tamil locale** (`React error #418`). `LangProvider` read `localStorage` inside its
`useState` initialisers, so the first client render disagreed with the server HTML, React
threw the tree away and rebuilt it. Two fixes:

1. the root layout passes the cookie-resolved locale down as `initialLocale`, so the
   **served HTML is now in the reader's language** — with `yazhi-locale=en` the SSR body
   carries English chrome, with `=hi` Devanagari (this was previously Tamil-then-corrected);
2. the saved display preference and locale are restored in an effect after hydration, never
   during render.

Verified in Chromium (headless, three locales): `/app?ws=nyaya` for `ta`/`en`/`hi` —
`<html lang>` correct, zero console errors, zero page errors, composer and library copy in
the right language at SSR (அனுப்பு / Send / भेजें).
